# ADR-004: Browser Extension Auto-Fill & User Gesture Policy

## Status
Accepted

## Date
2026-10-21

## Context
In the original browser extension (`extension/`):
1. `content.js` scanned all input fields on `DOMContentLoaded` and immediately posted a `"page_loaded"` message requesting credentials.
2. If the vault returned a single match for the domain, `content.js` automatically filled username and password into the DOM without user interaction.
3. `background.js` trusted the `url` sent in the JSON payload from `content.js` (`message.url`), rather than using `sender.tab.url` verified by the browser.
4. `manifest.json` set `"all_frames": true` without verifying `sender.frameId === 0`.

This exposed users to silent credential exfiltration: a malicious advertisement or iframe could include hidden password fields or post forged `message.url` payloads to steal bank credentials.

## Decision
1. **Require Explicit User Gesture (Default)**:
   - Credentials are never auto-filled on page load by default.
   - Auto-fill requires an explicit user action:
     - Selecting an entry from the extension popup, or
     - Clicking an in-field badge/shield rendered inside the input field by `content.js`.
2. **Opt-In `autofill_on_load`**:
   - Provide an explicit setting `integration.autofill_on_load` (default: `false`).
   - If enabled by the user, auto-fill only occurs on exact origin matches.
3. **Strict Top-Frame Isolation**:
   - Change `manifest.json` to `"all_frames": false`.
   - In `background.js`, assert `sender.frameId === 0` on all incoming tab messages; drop messages from subframes.
4. **Authoritative Browser-Verified Origin**:
   - `background.js` must ignore `message.url` from the message payload and strictly use `sender.tab.url`.
   - Match against the exact origin (`scheme + host + port`, e.g., `https://example.com:443` or `https://example.com`), rejecting substring or prefix matches.
   - No Public Suffix List (PSL) is used to avoid external dependencies and data files. Sub-domain matching is explicitly out of scope for this release and noted as a future option.

## Consequences
- Silent background credential harvesting via rogue iframes or hidden forms is completely blocked.
- User-facing behavior changes from passive auto-fill to gesture-initiated fill (badge or popup). README will be updated to document this behavior.
