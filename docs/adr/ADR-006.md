# ADR-006: Atomic Vault File Replacement Across Platforms

## Status
Accepted

## Date
2026-10-21

## Context
When persisting changes to disk, `VaultIO::save_vault()` writes the encrypted ciphertext to a temporary file (`<path>.tmp`), sets file permissions to `0600`, and then calls `std::filesystem::rename(temp_path, path)`.

On Windows, the C++ standard library implementation of `std::filesystem::rename` calls `MoveFileExW` without the `MOVEFILE_REPLACE_EXISTING` flag. If the target vault file already exists, `rename` throws `std::filesystem::filesystem_error` (`ERROR_ALREADY_EXISTS`), preventing subsequent saves and corrupting user workflow.

Furthermore, on POSIX systems, creating a temporary file with default `std::ofstream` creates the file with the process umask (typically `0644` or `0664`), briefly exposing the encrypted ciphertext to other local users before `chmod(0600)` is called.

## Decision
Implement a robust, platform-aware atomic file replacement strategy:

1. **POSIX Platform Implementation (Linux & macOS)**:
   - Generate a unique temporary filename within the same directory as the target vault file (e.g., `.<filename>.tmp.XXXXXX`) to ensure source and destination reside on the same filesystem mount point.
   - Open the unique temporary file using `open(temp_path.c_str(), O_WRONLY | O_CREAT | O_EXCL, 0600)`.
   - The combination of `O_CREAT | O_EXCL` and mode `0600` guarantees that the file is freshly created with restrictive permissions from inception, completely eliminating both symlink attacks and the umask race condition window.
   - Write ciphertext payload.
   - Call `fsync(fd)` to flush file data and metadata to physical storage.
   - Close file descriptor `close(fd)`.
   - Atomically rename temporary file over target: `rename(temp_path.c_str(), target_path.c_str())`.
   - Synchronize the parent directory: open parent directory descriptor with `O_RDONLY`, invoke `fsync(dir_fd)`, and close `dir_fd`.
   - **Failure handling**: If any error occurs prior to successful rename, immediately unlink the temporary file (`unlink(temp_path.c_str())`). Never leave temporary files behind.
2. **Windows Platform Implementation**:
   - Generate a unique temporary filename in the same directory (e.g., `.<filename>.tmp.<pid>_<counter>`).
   - Open file with `CreateFileW` (`GENERIC_WRITE`, `FILE_SHARE_READ`, `CREATE_NEW`).
   - Write ciphertext payload.
   - Flush file buffers to disk via `FlushFileBuffers(hFile)`.
   - Close handle via `CloseHandle(hFile)`.
   - Atomically swap using `MoveFileExW(temp_wpath.c_str(), target_wpath.c_str(), MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`.
   - **Failure handling**: If write, flush, or move fails, delete the temporary file via `DeleteFileW(temp_wpath.c_str())` before propagating the exception. Never leave temporary files behind on failure.

## Consequences
- Vault saves succeed reliably on Windows without `ERROR_ALREADY_EXISTS`.
- Umask race condition on Unix systems is eliminated.
- Changes are guaranteed flushed to physical media before atomic pointer swap.
