# ADR-007: CMake Interface Targets & Compiler Hardening Structure

## Status
Accepted

## Date
2026-10-21

## Context
In the original CMake configuration:
1. `cmake/PwledgerCompilerMSVC.cmake` defined `function(apply_pwledger_compile_options_to_target)`, but this function was never invoked anywhere in `CMakeLists.txt`, `src/CMakeLists.txt`, or `apps/CMakeLists.txt`. As a result, MSVC builds compiled with default compiler flags and completely lacked security flags like `/GS`, `/sdl`, `/guard:cf`, `/NXCOMPAT`, `/DYNAMICBASE`, and `/WX`.
2. `cmake/PwledgerCompilerUnix.cmake` injected flags globally into `CMAKE_CXX_FLAGS`, violating modern CMake best practices and contaminating third-party subprojects or tests.
3. Obsolete legacy variables (`TOP_DIR`, `PWLEDGER_DIR`, `PWLEDGER_DIR_PREFIXES`) cluttered `CMakeLists.txt`.

## Decision
Refactor build flags into a modern CMake `INTERFACE` target:

1. **Create `pwledger_hardening_flags` Target**:
   - Defined in `cmake/PwledgerHardening.cmake`:
     ```cmake
     add_library(pwledger_hardening_flags INTERFACE)
     target_compile_features(pwledger_hardening_flags INTERFACE cxx_std_20)
     ```
   - All warning flags, security flags, definitions (`_FORTIFY_SOURCE=3`), and linker options are attached via `target_compile_options()` and `target_link_options()`.
2. **Explicit Target Linkage**:
   - `pwledger_core`: links `pwledger_hardening_flags` `PUBLIC`.
   - `pwledger-cli`, `pwledger-host`, and `tests`: link `pwledger_core` (inheriting flags transitively) or link `pwledger_hardening_flags` `PRIVATE`.
3. **Multi-Toolchain Parity**:
   - MSVC: `/W4 /WX /permissive- /GS /sdl /guard:cf /NXCOMPAT /DYNAMICBASE /HIGHENTROPYVA`.
   - GCC / Clang: `-Wall -Wextra -Wpedantic -Werror -fstack-protector-strong -D_FORTIFY_SOURCE=3 -Wl,-z,relro,-z,now -Wl,-z,noexecstack -fPIE -pie`.
4. **Clean House**:
   - Delete unreferenced `apply_pwledger_compile_options_to_target` and remove dead `TOP_DIR` variables.

## Consequences
- 100% of MSVC security hardening flags are active and enforced on Windows.
- Target properties are scoped cleanly without leaking into parent or subproject scopes.
- Modern CMake conventions are fully respected.
