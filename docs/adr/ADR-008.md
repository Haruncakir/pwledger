# ADR-008: Secret-Safe Observability & Structured Diagnostic Logging

## Status
Accepted

## Date
2026-10-21

## Context
Across the original codebase:
- Diagnostics were printed using ad-hoc `std::cerr << ...` statements with inconsistent formats and no severity levels.
- Some error statements printed string values that could inadvertently format or display user input or credentials on failure paths.
- In `pwledger-host`, logging directly to `std::cout` is catastrophic because `stdout` is the binary framing pipe for Native Messaging; any stray text written to stdout corrupts the browser protocol.

## Decision
1. **Lightweight Structured Logging Helper**:
   - Provide minimal, dependency-free logging utilities in `include/pwledger/Common.h`:
     ```cpp
     enum class LogLevel { Debug, Info, Warn, Error };
     void log_message(LogLevel level, std::string_view component, std::string_view msg);
     ```
   - Format: `[TIMESTAMP] [LEVEL] [component] message\n`
   - Destination: Exclusively `std::cerr` (never `std::cout`).
2. **Secret-Safe Formatting Contract**:
   - Loggers accept only explicitly sanitized metadata (e.g. entry UUID, username, domain origin).
   - Functions accepting `Secret`, `SecureBuffer`, or raw password spans do not have overloads for `log_message()`.
   - In Debug builds, sensitive variables are masked (e.g. `[REDACTED]`).
3. **Native Host Stdout Guard**:
   - In `apps/native_host/main.cc`, redirect or audit all output to guarantee that `stdout` is used exclusively by `NativeMessaging::write_message()`.

## Consequences
- Uniform diagnostic format across CLI and native host.
- Zero possibility of stdout framing corruption in Native Messaging.
- Zero accidental leaks of plaintext passwords into terminal scrollback or log streams.
